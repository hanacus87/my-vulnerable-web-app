## 1. 概要

**Path Traversal** とは、ファイル名やパスとして扱われる入力値に `../` などの相対パスを混入させることで、アプリが想定したディレクトリの外のファイルを読み書きできてしまう脆弱性です。

## 2. 脆弱なコードと攻撃

### 脆弱なコード

`src/profile_update.php`:

```php
$newName = $_FILES['avatar']['full_path'];
```

### 攻撃（保存先ディレクトリの逸脱）

本アプリは保存名を `$_FILES['avatar']['full_path']` から採り、`move_uploaded_file()` の保存先 `uploads/avatars/` に連結します。リクエストのファイル名について、 `full_path` は `../` などを無害化しません。そのため送信されたファイル名がそのまま保存先の組み立てに使われ、`../` を含めると `avatars/` の外へ逸脱します。

#### 手順

1. 有効な画像ファイルを用意する。

2. アイコン更新のリクエストについて、ファイル名に `../` を含めて送信する。ブラウザの通常のファイル選択では `../` を送れないため、Burp Suiteなどを利用し、ファイル名を修正してからリクエストを送信する。

3. 保存先が `avatars/` の外へ逸脱する。

   ```
   uploads/avatars/ + ../pwned.png  =>  uploads/pwned.png
   ```

   本来 `uploads/avatars/` にしか作られないはずのファイルが、その親 `uploads/` 直下に作成されます。`move_uploaded_file()` は上書きも行うため、書き込み可能な場所にある既存ファイルを狙って上書きすることもできます。

## 3. 原因と修正

### 原因

**ファイルの送信側が指定したファイル名を、そのまま保存名に採用している**ため、ファイル名に `../` などを含めると保存先が `avatars/` の外へ移動します。

### 修正

**保存名をサーバ側で生成**し、**拡張子もホワイトリストで指定**します。こうすると保存先のパスにリクエストの入力が混ざらなくなり、`../` などを注入する余地が無くなります。

```diff
// 修正前
- $newName = $_FILES['avatar']['full_path'];

// 修正後
+ $newName = bin2hex(random_bytes(16)) . '.' . $allowed[$mime];
```

> [!Note]
> どうしても送信ファイル名を使いたい場合、自動的にディレクトリ部分の除去を行う `$_FILES['avatar']['name']` を使用しましょう。また、保存先を `realpath()` で解決して所定ディレクトリ配下かを確認する、といった防御も有効です。
